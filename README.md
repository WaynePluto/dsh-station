# DSH 工作站（dsh-station）

**简体中文** | [English](README.en.md)

当前内置 dsh：`0.2.0-rc.2`（next 通道，developer preview）

官方 DeepSeek Harness（dsh）的完整工作站。桌面应用自带 dsh，装好就能用；远程访问是内置的可选功能，默认不开，需要时再启用。

- 自带 dsh，不需要单独安装；升级 dsh-station 就是升级 dsh
- 不改 dsh、不 fork，扩展全部走插件：dsh 自带的 40 个官方 UI 插件原样可用，另有 20 个随附功能组件（模型增强、会话增强、开发工具等）
- 只用本机就是完整体：首次打开不需要创建账号，远程设置一概不用碰
- 远程功能按需启用：被开放的机器不监听公网端口，由它主动外拨，路由器不用做端口映射；所有非本机的浏览器访问都要登录（密码 + TOTP 动态码）

每台装了 dsh-station 的机器都一样：本机跑 dsh，外加一个控制台和一个拨号器。开远程之后，唯一的区别是你把哪台当入口机器，也就是浏览器实际打开的那台。

## 需要准备什么

| | 要求 |
|---|---|
| 操作系统 | Windows / Linux / macOS |
| Node.js | **轻量版（lite）与服务版需要 22.19+**（[nodejs.org](https://nodejs.org) 装 LTS；`node -v` 可查版本）；**桌面完整版（full）自带 Node，无需安装** |
| 网络 | 被开放的机器能连到入口机器；入口机器在公网时需要能被访问到 |
| dsh | **不需要安装**，已随包内置 |

## 安装

从 [Releases](../../releases) 下载对应平台的介质（dsh 已随包携带）。共四个发布端：Windows / macOS / Linux 桌面版与 Linux 服务版 zip。每个介质分轻量版（lite）/ 完整版（full）两种，桌面版再分 setup（安装包）与 portable（便携 zip）两种形态：

| 功能 | 轻量版（lite） | 完整版（full） |
|---|---|---|
| dsh 核心功能 | ✅ | ✅ |
| Office 文档预览 | ❌ | ✅ |
| Node 运行时 | ❌ | ✅（内置版本 v24.21.0） |

| 发布端 | setup（安装包） | portable（便携 zip） |
|---|---|---|
| Windows 桌面版 | `…-desktop-<变体>-setup.exe` | `…-desktop-<变体>.zip` |
| macOS 桌面版 | `…-desktop-<变体>.dmg`（拖入 Applications） | `…-desktop-<变体>.zip`（内含 .app） |
| Linux 桌面版 | `…-desktop-<变体>.deb` | `…-desktop-<变体>.zip` |

第四个发布端是 Linux 服务版 zip（`…-linux-x64-server-<变体>.zip`）：面向无桌面服务器，解压后跑 `./start.sh`，始终要求系统 Node ≥ 22.19.0，不携带 Node 二进制。

- 轻量版不内置 Node.js，先自行安装 22.19 以上再启动；完整版自带固定版本 Node，装好即用
- 安装包与可执行文件未签名，SmartScreen / Gatekeeper 可能提示未知发布者
- macOS 桌面版未公证，首次打开需在「系统设置 → 隐私与安全性」里放行

> 包分平台是因为 dsh 的依赖带预编译平台二进制；dsh-station 自己的代码零原生模块。

### 随附功能插件

首次启动 `dsh-station-web` profile 时，会通过 dsh 官方插件管理器默认安装并启用 10 个随附的第三方 Bundle，共 20 个功能组件：4 个组合包（远程体验、模型增强、会话增强、开发工具）加 6 个独立包（网页目录选择、出网代理、简洁模式、全局提示词、文件浏览、固定 YOLO）。

- 组合包可整体停用或卸载，组件通常也可在详情页单独停用。模型增强里的「模型目录更新」与「模型能力与协议」共同参与启动屏障，当前不要单独关闭其中一个
- 网页目录选择需要静态覆盖 dsh 原生目录选择器，所以独立分发
- 升级 dsh-station 会配套升级所有仍安装的随附包（含已停用的），停用状态保留
- 卸载后不自动补回。要恢复时在 dsh「添加插件」里填 `<解压目录>/plugins/<包目录>` 的绝对路径，再启用该 Bundle，装的是当前发行版随附的版本
- 旧 profile 里不再随附的第三方插件，请在 dsh 官方插件管理器手动卸载；launcher 不清理这些条目，也不动其他 profile
- 「设置 → 代理」可选跟随环境（默认）、插件代理地址或强制直连；作用于原生 fetch 和官方网页抓取，不保证接管子进程或独立网络库
- 图片预览放大后，在图片滚动区域按住 Space 并用鼠标左键拖动可平移；真实浏览器效果待实机验收
- connection 的 webServer 注入是壳级常驻 overlay，浏览器 RPC 靠它工作，不属于可停用插件

也可以从源码打包，产物与 Releases 下载的完全一致：

```bash
git clone <本仓库地址> dsh-station
cd dsh-station
pnpm install
pnpm release
```

发布命令按发布端 × 变体拆分：`pnpm release:win:lite` / `pnpm release:win:full`，mac、linux 同理；`release:linux:<变体>` 会同时产出对应变体的服务版 zip；只要服务版（或本机不是 Linux 也要打服务版 zip）时用 `release:linux-server:<变体>`，它在任意平台都能执行。`pnpm release` 一次打本机能产的全部，即本机桌面双变体加 Linux 服务版。统一入口是 `scripts/release.mjs`：构建一次后串起两个打包脚本，`--skip-build` 复用现有 dist。

完整版首次打包会下载随包 Node，约 30 MB/平台，之后缓存在 `.dev/desktop-toolchain` 不再重复下载；国内可设 `DSH_STATION_NODE_DIST_MIRROR=https://npmmirror.com/mirrors/node` 走镜像。只要轻量版就用 `:lite` 命令，完全跳过下载。

桌面壳是 Wails 2（Go）应用，依赖系统 WebView/CGO 工具链，只能在对应平台构建，其余平台由 release 工作流的原生 runner 打包。打包要求 pnpm ≥ 10：本地直接用你已安装的版本，CI 固定 10.17.0 以保持可复现。

## 第一次启动

**桌面版**：安装或解压后双击启动，窗口里就是 dsh 工作台。桌面壳是 Wails 2（Go + 系统 WebView）单窗口应用，本机的后台进程由它拉起和托管。本机使用不需要创建账号，退出走托盘菜单「退出」。要用远程能力时，第一次打开「远程管理」页会引导创建管理员、密码和 TOTP，见[远程能力（可选）](#远程能力可选)。

**Linux 服务版**：在想当入口机器的那台机器上解压，运行 `./start.sh`。第一次还没有管理员账号，终端会打印形如 `http://127.0.0.1:30809` 的设置页地址，浏览器打开完成初始化，三步见[启用远程入口](#启用远程入口)；无桌面服务器可用 [CLI 初始化](deploy/README.md)。

> 只用本机？到这里就够了。dsh 的全部能力加 20 个随附功能组件都在本机工作台里，不需要账号；下文的远程配置想用了再回来读。

## 远程能力（可选）

启用后，手机、平板或异地电脑的浏览器可以继续指挥这台机器。有多台机器时，选一台当入口机器，其余机器通过它对外开放；浏览器打开哪台，就是指挥哪台。

### 它是怎么连起来的

> 每台机器都跑着自己的 dsh，AI 读写文件、执行命令都发生在那台机器本地。打开 pc2 的页面，就是 pc2 上的 dsh 在动 pc2 的代码，pc1 只负责转发。选机器 = 选代码在哪台机器上。

```
                    ┌──────────────────────────────────────┐
   手机 / 平板       │  pc1（入口机器，比如一台云服务器       │
   异地电脑     ───> │  或者你家里那台常开的电脑）           │
   浏览器            │                                      │
                    │   控制台   ←── 登录、路由、机器列表     │
                    │      ↑  ↑                            │
                    │      │  └──> pc1 自己的 dsh          │
                    └──────┼───────────────────────────────┘
                           │
              反向隧道（由被开放的机器主动拨出，不需要公网 IP）
                           │
              ┌────────────┴────────────┐
              │                         │
      ┌───────┴────────┐       ┌────────┴───────┐
      │  pc2            │       │  pc3           │
      │  拨号器 ──> dsh │       │  拨号器 ──> dsh│
      └────────────────┘       └────────────────┘
        公司台式机                 家里的笔记本
```

- 关系是单向的：pc1 能打开 pc2，pc2 打不开 pc1；任意一台都能当入口机器
- 被开放的机器不需要公网 IP，不需要端口映射
- 没有公网域名时，每台挂上来的机器在入口机器上分到一个固定端口，如 `http://10.1.2.87:30810` 就是 pc2；入口机器配置 `relay.domain` 并前置泛域名 TLS 反代后，改用 `https://pc2.你的域名` 子域名访问，新增机器不需要加 DNS 或反代配置（公网推荐，见[部署说明](deploy/README.md)）
- dsh 永远只监听 `127.0.0.1`，对外的门全由控制台把守

### 启用远程入口

首次打开管理界面（桌面版在「远程管理」页，服务版就是终端打印的设置页地址），在这台机器上完成三步：

1. 填账号名，默认 `admin`，可改成字母数字和 `. _ -`；设管理员密码，至少 6 个字符，大写、小写、数字、符号至少用 3 类
2. 用验证器 App 扫页面二维码，Microsoft / Google Authenticator、1Password 都可以
3. 输入 App 里的 6 位动态码确认

以后从手机或别的电脑访问，都用这个账号名加密码和动态码登录。忘了账号名，就在这台机器上打开控制台的「账号」页看。

> 🔒 设置向导只对 `127.0.0.1` 开放。局域网里其他人只会看到「请到那台机器上完成设置」，抢注不了管理员。无桌面服务器够不着向导，见下面「救急」。

设好后重启一次，全部访问地址就打出来了：服务版看终端输出，桌面版在「远程管理」页看。

```
  ✓ Node v22.19.0
  ✓ dsh 已就绪           127.0.0.1:3080
  ✓ pc1 的控制台已启动   0.0.0.0:30809
  ○ 没有远程入口         pc1 只能从本机和局域网打开

  ┌────────────────────────────────────────────────────┐
  │  本机控制台   http://127.0.0.1:30809     免登录    │
  │  局域网访问   http://10.1.2.87:30809   需登录    │
  └────────────────────────────────────────────────────┘
```

在这台机器上打开 `http://127.0.0.1:30809` 免登录，只有回环地址有这个待遇，启用了公网域名后这个本机地址仍然保留。dsh 的地址不对外打印，一律走控制台，由它替你完成 dsh 0.1.2 起自带的 token 交换。终端里 `Ctrl+C` 退出，三个进程一起关掉。

### 把第二台机器挂上来

1. 在 pc2 上同样启动 dsh-station。它会提示「没有远程入口」，正常，先挂着
2. 在 pc1 打开 `http://127.0.0.1:30809/_admin`，「让另一台机器通过 pc1 开放」里填 pc2 的机器名，点签发，页面会给出一条可直接复制的命令。配置公网域名时命令用 `wss://dsh.example.com`，即使在 pc1 本机的 `127.0.0.1` 页面签发，也不会把回环地址发给 pc2：
   ```
   dsh-station-connector --relay ws://192.168.1.10:30809 --slug pc2 --enroll-token xxxxx --hub-authority 192.168.1.10
   ```
3. 到 pc2 的控制台「远程入口」页（`http://127.0.0.1:30809/_admin/hub`），把整条命令粘进唯一的输入框，提交

pc2 立刻连上，不用重启，并在 pc1 上分到固定端口。之后从 pc1 的地址加该端口打开的就是 pc2 上的 dsh。

> 令牌一次性，5 分钟有效。pc2 注册完设备公钥，令牌即失效删除，不会再显示第二次；过期就重新签发。
>
> pc2 的 dsh 会自动重启一次以信任 pc1 的地址，「远程入口」页有重启进度。之后公网域名模式下日常打开 `https://pc2.你的域名`；入口机器自己仍用 `http://127.0.0.1:30809` 或 `https://pc1.你的域名`。
>
> 取消远程入口不用重新签令牌：那台机器的「远程入口」页会记住上次的入口，点「重新连接」一键挂回；入口机器的「机器」页也会把它标成「已断开 · 可唤醒」，点「请求上线」约一分钟内自己连回来。只有入口机器执行过「停止并移除」，才需要重新签发令牌再粘一次。

### 日常操作

全部在浏览器里完成。控制台 `/_admin` 共三个 tab，每页顶部标着「你正在管理 pc1」，两台机器的控制台长得一样，靠这一行区分：

| tab | 地址 | 管什么 |
|---|---|---|
| 机器 | `/_admin` | 通过本机开放的机器、签发注册令牌 |
| 远程入口 | `/_admin/hub` | 本机挂在谁身上，设置 / 取消 / 一键重连 |
| 账号 | `/_admin/account` | 改密码、重置验证器 |

| 想做什么 | 在哪 |
|---|---|
| 看能打开哪些机器 | 「机器」 |
| 多开放一台机器 | 「机器」→「让另一台机器通过…开放」 |
| 把一台停掉的机器叫回来 | 「机器」→ 断开的机器点「请求上线」，约一分钟内连回 |
| 把一台机器停掉并摘出去 | 「机器」→ 在线机器「停止…并移除」，对方机器上的 dsh-station 会整个退出；离线机器只能「移除」，停不到它上面运行的服务 |
| 设置 / 取消本机的远程入口 | 「远程入口」 |
| 挂回上次取消的远程入口 | 「远程入口」→「重新连接」，不需要新令牌；对方已「停止并移除」过本机时才要重新签发 |
| 改管理员密码 / 验证器换手机 | 「账号」 |
| 看最近发生了什么 | 网页里没有这个页，见下面「安全须知」 |

#### 救急：万一网页进不去

只留给两种情况：无图形界面的服务器首次部署，或密码和验证器都丢了。

```bash
node dist/relay.js init          # 创建管理员（服务器首次部署）
node dist/relay.js passwd        # 重设管理员密码
node dist/relay.js totp reset    # 重置验证器，重新扫码
```

> 三条命令都在解压后的包目录里执行；源码仓库里调试时对应 `pnpm relay:init` / `pnpm relay:passwd` / `pnpm relay:totp-reset`。
>
> 这些命令不问旧密码。能在这台机器上执行命令的人，本来就能直接读写数据库文件，真正要守住的是这台机器本身的登录。云服务器上设置向导只对 `127.0.0.1` 开放，本地浏览器够不着，用 `init` 创建管理员，或用下面的 SSH 端口转发把向导借到本地。

服务器首次部署也可以不跑 `init`，在你自己的电脑上挂一条 SSH 隧道：

```bash
ssh -L 30809:127.0.0.1:30809 user@服务器地址
```

隧道保持期间，本地浏览器打开 `http://127.0.0.1:30809`。请求经隧道落在服务器的回环地址上，向导照常放行，还能直接扫码绑定验证器。注意必须用 `127.0.0.1:30809` 这个地址打开，Host 保持回环才免登录。向导只在首次部署用一次，配好即可断开隧道，日常走服务器公网地址登录。

## 安全须知

启用远程能力，就是把这台开发机交给浏览器指挥。启用前读一遍，其中固定 YOLO 一条即使只用本机也适用：

- 不要在没有 HTTPS 的情况下暴露到公网。局域网 HTTP 是权衡后可接受的，启动时会打印高危警告；公网必须套 HTTPS，用 Caddy 之类自动证书
- dsh 自己没有任何认证，只听 `127.0.0.1`，所有门都在控制台这层。控制台账号被突破等于机器沦陷：能开会话就能跑命令
- 登录连错 5 次锁 15 分钟
- 默认是固定 YOLO 模式：`dsh-station-web` 隐藏权限选择器，`bash` / `pwsh` / `write` / `edit` 直接按 dsh 进程用户权限执行，合法的权限请求自动允许；停用 `yolo-mode` 插件并重启 dsh 才能恢复 dsh 原生权限保护。`ask_user_question` 仍会向你提问
- Linux systemd 部署以个人普通用户运行，默认访问该用户的家目录；管理员操作通过交互终端里的明确 sudo 命令完成，保留系统 sudo 缓存，不建立 root shell。运行数据在 `~/.dsh-station`，官方 dsh 数据在 `~/.dsh`，详见[部署说明](deploy/README.md)
- 安全记录不在网页里。登录成败、机器挂载/移除、改密码/重置验证器等事件同时写 relay 日志（JSON 行，`"audit":true`）和 `relay.db` 的 `audit_log` 表，永不自动过期；要查就在跑 relay 的机器上查
- 威胁模型与已知取舍见 [docs/04-security.md](docs/04-security.md)

## 遇到问题

| 现象 | 原因 |
|---|---|
| 提示 Node 版本太低 | 装 22.19 以上 |
| 局域网打不开，本机能开 | 防火墙没放行。Windows：`New-NetFirewallRule -DisplayName "dsh-station" -Direction Inbound -LocalPort 30809 -Protocol TCP -Action Allow` |
| 密码明明是对的却登不上 | 看启动日志有没有「pre-scrypt password hash」告警，有就在本机管理页重设一次密码 |
| 被开放机器的界面报 403 | 那台机器的 dsh 不信任入口机器地址。粘完命令后 dsh 会自动重启并信任新地址；若它的「远程入口」页显示自动重启失败，按页面提示手动重启那台机器的 dsh-station |

## 本地开发与调试（开发者向）

`pnpm run dev` 是开发调试栈，不是安装方式。它会构建功能插件、生成 `.dev/plugins/` 安装介质，再在仓库同级准备按依赖指纹隔离的 dsh 运行时；该运行时不含工作区同名插件安装锚，保证 dsh 实际加载的是装进 profile 的第三方 Bundle。之后开发栈执行与发行版相同的首次安装、升级、停用和卸载记忆逻辑，并打印可用于重装的 `.dev/plugins/` 路径。

relay 数据库、设备密钥、membership 和 JWT 密钥复用发行版默认的 `~/.dsh-station`；dsh 设置、profile 与会话用标准 `~/.dsh`。不要让开发栈和已安装的发行版同时运行，它们会争用端口并共享设备身份。`pnpm start` 只运行已有构建产物，不做 `pnpm run dev` 那套插件构建、介质生成与隔离运行时准备。

```powershell
pnpm run dev   # 构建插件、生成 .dev/plugins、准备隔离 dsh 运行时并启动源码栈
pnpm start     # 运行已有 dist 产物；先确保上述开发介质和运行时已经生成
```

开发环境卸载的插件不会自动补回，从 `<仓库>/.dev/plugins/<包目录>` 重装。Windows 上仓库与 profile 跨盘时，内置 pnpm 代理会自动改用 profile 内的同盘介质镜像，避免本地目录链接失效，安装入口仍填 `.dev/plugins` 路径。开发约定与常用检查见 [AGENTS.md](AGENTS.md)。
