# 首次插件准备：有界文件复制优化

2026-09-29，基于 `9e0e11f` 工作树实现；对照环境沿用 [Node 24.19.0 基准](startup-benchmark-node24.md)。
本轮仅优化 launcher 的首次/升级介质准备，不改官方 dsh、插件集合、链接布局、认证、ready 或退出语义。
用户随后已确认第一轮优化通过；后续缓存启动优化见 [第二轮报告](startup-development-optimization.md)。

## 实现

- `packages/launcher/src/plugin-copy.ts`：惰性遍历目录，最多 8 个在途文件操作，不为所有文件同时创建 Promise。
  普通文件通过 `copyFile` 复制，不改为硬链接；保留空目录、文件权限，目录权限在内容完成后恢复。
- 运行时包先解析真实源目录，复制时仍排除内部 `node_modules`，按已有依赖闭包展开。
  组合包的组件 `node_modules` 不排除。仅 pi-ai/http-proxy 保持原精确共享链接。
- root/内嵌符号链接沿用原生 `fs.cp` 的不解引用及错误语义；未扩大符号链接依赖。
  真实路径和目标现存祖先校验拒绝自身/子目录复制，包含 `..child` 与 junction 绕行情况。
- 首个错误发生后停止取新任务，等全部在途操作结束再拒绝；不会在调用方重试或清理后继续写文件。
- `plugin-lifecycle.ts` 在破坏性修改前写 `.dsh-station-plugin-media.pending`。
  复制、官方安装及 manifest/state 提交成功后才清除；异常或进程中断保留标记，下次禁止快路径。
  旧 offered 与用户停用/卸载选择保留，不通过删除整个状态文件强制重装。
- `onTiming` 回调只包含固定阶段和毫秒数，由 launcher 输出 `插件准备耗时 [phase]: Nms`。
  阶段为 check/plugin-copy/dependency-resolve/dependency-copy/install/state-write，只有完成才报告；
  缓存启动只有 check。不解析或修改 dsh 内部加载协议，不改变页面文案。

未实施：预生成发行文件清单、依赖目录共享扩展、开发入口合并、插件懒加载或后台保温。
依赖解析当前只有几十毫秒，本轮没有为它增加新的发行格式。

## 定位与复制器对照

真实开发介质的三次串行同步，总耗时 6.216/11.087/12.349s，
其中依赖复制 5.771/10.656/11.891s；依赖解析约 19–25ms、官方安装约 292–300ms。
复制是本轮主要目标，样本波动通过交错实验进一步控制。

交错实验使用同一份普通运行时依赖树，每轮为新目标目录：
11,359 个文件、70,136,384 字节。排除两项刻意共享的链接；它们另有生命周期身份测试。
每次结束后校验所有包内相对路径、空目录和文件字节，随后删除本次目标。

| 顺序轮次 | 原串行 cpSync | 新复制器 4 路 | 新复制器 8 路 |
|---|---:|---:|---:|
| 0：串行→4→8 | 5.800s | 1.910s | 1.670s |
| 1：8→串行→4 | 5.899s | 2.020s | 1.736s |
| 2：4→8→串行 | 5.744s | 2.137s | 1.685s |
| **中位数** | **5.800s** | **2.020s** | **1.685s** |

选择默认 8 路；复制中位耗时减少约 **71%**。
该收益代表整套新复制器（遍历、copyFile 与并发），不是单独改变并发参数的因果结论。
全部九个输出内容指纹一致：
`8e45246f12ddaecee645c3e1f72ed9604c88c9f99bd6b97cc7ae09dded9f4596`。

| 轮次 | 旧版 | 新版 |
|---|---:|---:|
| 0 | 3.080s | 3.126s |
| 1 | 3.059s | 3.051s |
| 2 | 2.972s | 2.916s |
| 中位数 | **3.059s** | **3.051s** |

缓存启动基本持平；本轮不宣称加速官方 dsh 本身，也不把有限样本当成跨设备性能保证。
未重启 Windows 或清空文件缓存，“首次”只表示应用数据首次初始化。

## 检查与限制

- launcher：23个测试文件，340通过、2跳过；跳过Windows不适用的POSIX权限位和未开启的开发桥真后端用例。
- 新增覆盖：真实文件/二进制/空目录、无硬链接、node_modules过滤、实际并发上限、失败停止与排空、
  原错误保留、真实路径校验、原生链接错误等价、pending重试、停用/卸载保留、固定计时字段。
- 同版本内容变化、迁移回滚、pi-ai/http-proxy真实共享模块身份等原有回归继续通过。
- 默认系统TEMP下未修改的 `dsh-restart.spec.ts` 可触发 Node/libuv `src\win\fs-event.c:72` 原生断言；
  改用仓库外D盘临时目录后完整测试通过。未豁免或修改该测试，未进一步归因此环境问题。
- launcher typecheck/build、全仓build、定向lint通过（index.ts仅既有describeChange警告）。
- 新版12次启动与6次交错对照均确认实际Node24.19.0、relay未监听、清理后dsh端口释放；
  清理使用taskkill，仅属于本次测试树，不代表优雅退出验收。
- 本轮computer-use诊断返回 `target_changed`（目标隐藏或其他虚拟桌面），未绕过后台约束。
  已取得窗口可见标志，但**新版截图、完整工作台交互、深浅主题仍待实机确认**；不沿用旧版截图冒充新版验收。
- macOS/Linux未实机验证，权限与成功创建符号链接的非Windows分支仍需目标平台验收。
