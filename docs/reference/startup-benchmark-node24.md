# Node 24.19.0 · Windows 桌面启动基准

2026-09-29，本机测试；工作站代码 `9e0e11f`，版本 `0.0.2-20260928`。
不修改 dsh、桌面壳或插件实现，不启用编译缓存，不改变系统安全设置。
本页保留优化前的对照样本；后续实现与复测见 [首次准备优化](startup-copy-optimization.md)。

## 结论

- 开发版与 Windows lite 便携版各测一次空数据初始化、五次缓存重启。
- 五次重启的后台登录入口就绪中位数：开发版 **3.752s**，便携版 **2.922s**。
- dsh 进程创建至登录入口就绪中位数：开发版 **2.635s**，便携版 **2.593s**。
- 便携版总耗时少约 **0.831s**，主要差别在 dsh 创建前的开发入口/准备流程，而非 dsh 自身。
- 两种版本均已在实际 WebView2 窗口看到原生工作台和首次「内测声明」。没有代为接受声明或发送模型请求。
- 本次没有旧 Node 的同条件 A/B 对照，不能把与历史记录的差异直接归因于 Node 升级。

## 测量口径

- **起点**：基准父进程调用 spawn 前。开发版包括 pnpm run 与开发入口；便携版直接启动解压后的 exe。
- **窗口可见**：每约 25ms 只读枚举本次进程树的顶层窗口，匹配壳 PID、可见状态及工作站标题。
  这是窗口可见，不是页面已经绘制。
- **dsh 创建**：从 Windows `GetProcessTimes` 读取实际创建时间，结束后按存活进程命令行在内存中确定角色；不保存命令行。
- **端口监听**：每约 25ms 对本机 dsh 端口做 TCP 探测，包含采样误差；不是业务/插件全部就绪。
- **登录入口就绪**：父进程收到壳转发的 `dsh web:` 日志行，包含很小的管道/日志转发延迟。
  token 已在壳中脱敏，采集器再次脱敏；不记录 token、Cookie 或业务响应。
- 每轮有界等待；采样结束仅通过 `taskkill /T /F` 回收本次进程树，验证 dsh 端口释放。
  本次不把强制清理作为优雅退出/托盘退出验收。

系统 pnpm 启动器在隔离 home 下尝试联网获取 `@pnpm/exe` 并失败，未进入桌面流程。
正式开发样本因此使用已有的固定 CLI 执行相同 `run dev:desktop` 脚本：

```powershell
node node_modules/pnpm/bin/pnpm.cjs run dev:desktop
```

这避免了包管理器自举下载，但不包含系统 pnpm shim 的版本选择和 PowerShell 启动开销。
构建缓存已就绪；正式样本中的「首次」是空 profile/WebView2 数据初始化，不是全新源码克隆或换 Node 后首次构建。
所有测试均在同一 Windows 会话完成，未重启系统、未清理文件缓存，不能称为系统冷启动。

### 页面计时边界

生产 go-webview2 会清除外部 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` 和用户数据目录覆盖，
因此不能只靠这些环境变量让原样发行 exe 开启 CDP。依据为依赖的
`webviewloader/env_create.go`、`native_module.go`；默认数据目录依据 `pkg/edge/chromium.go`。
本次没有修改产品或依赖来开放调试端口，改用实际默认读取的 `APPDATA` 隔离数据。

原生 UIA 仅取得壳窗口控件，没有完整网页树；最终页面通过明确 PID 的窗口截图确认。
**未取得精确 FCP、原生 BootPage 消失或可交互时刻**，下表不能当作端到端页面可用时间。
调试采集器期间的样本不纳入正式统计；只采用 `dev-baseline-0..5`、`portable-baseline-0..5`。

### 五次缓存重启汇总

括号中为最小–最大值，各列中位数独立计算，不能直接相加。

| 指标 | 开发版 | lite 便携版 |
|---|---:|---:|
| 窗口可见 | 0.792（0.790–0.848） | 0.648（0.604–0.668） |
| dsh 创建 | 1.093（1.073–1.136） | 0.343（0.310–0.364） |
| 端口监听 | 3.410（3.346–3.495） | 2.651（2.605–2.678） |
| 登录入口就绪 | 3.752（3.659–3.885） | 2.922（2.909–3.022） |
| dsh 创建→端口监听 | 2.293（2.253–2.423） | 2.292（2.249–2.368） |
| dsh 创建→登录入口 | 2.635（2.566–2.813） | 2.593（2.553–2.712） |

首次初始化的额外耗时主要在 dsh 创建前的插件介质准备；日常缓存重启没有重复执行该完整流程。
两种模式 dsh 自身耗时接近，下一步若优化「正在启动 dsh…」阶段，应以约 2.6s 为本机新基线。
本次未重新采集 CPU/文件 IO，不更新此前瓶颈归因。
