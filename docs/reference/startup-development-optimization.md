# 第二轮：开发准备提速与插件启动归因

2026-09-29。第一轮有界复制优化已由用户确认通过；本轮仅保留开发准备优化。
基准环境沿用 [Node 24.19.0](startup-benchmark-node24.md)，首次准备的收益见 [第一轮](startup-copy-optimization.md)。
不修改官方 dsh、认证、ready、模型初始化屏障、插件选择或系统安全设置。

## 最终实现

- `scripts/dev-runtime.mjs` 导出 `ensureDevelopmentRuntime()`，导入模块本身不读写配置或安装依赖。
  独立 CLI 入口保留；`dev-stack.mjs` 仍可按原方式调用。
- `dev-desktop-prepare.mjs` 在准备子进程内直接调用该函数，不再为 runtime 多启动一次 Node。
  runtime 完成后才加载 `local-config.mjs`，原运行时描述一致性检查保留。
- 根 package.json、pnpm-workspace.yaml、pnpm-lock.yaml **每次完整读取并计算 SHA-256**，
  成功校验的内容摘要保存在 `node_modules/.cache/dsh-station/dev-runtime-validation.json`。
  摘要与缓存版本命中时才跳过 YAML import/parse；内容改变、缓存丢失或损坏都重新校验。
  不是 mtime/size 缓存，同长度并恢复原时间戳的 lockfile 漂移也会拒绝。
- launcher dependencies、根 overrides 每次重新读取，运行时目录指纹算法与目录布局不变；
  dsh、安装锚和 pnpm 入口缺失仍重建。解析失败不推进校验缓存，安装失败不发布 runtime 描述。
- 保留 wrapper → 准备子进程/launcher 的所有权边界、早期无凭据握手、排队命令与取消回收。
  不把长时间 pnpm install/build 塞入控制桥主线程，准备期间退出仍能回收整棵子进程树。

新增 `scripts/dev-runtime.spec.ts`，并纳入 launcher 的 Vitest 配置；发行版运行代码没有本轮改动。

## 插件归因与未采纳项

使用隔离profile，按其所属便携运行时启动；先断言插件介质 pi-ai 与 dsh 的真实包目录一致。
只在实验profile按组停用，不改日常选择。15次有效采样中，每组3次中位数（dsh命令→登录日志）：

| 实验组 | 中位数 |
|---|---:|
| 官方Bundle＋壳级基础设施 | 1.882s |
| 全部默认插件 | 2.286s |
| 全部但停用Copilot组件 | 2.291s |
| 全部但停用模型增强Bundle | 1.976s |
| 全部但停用开发工具Bundle | 2.237s |

差值不是可直接相加或删除的业务成本。模型目录恢复与协议覆盖必须先于原生模型校验；
终端/工具注册也不能为了提前ready而延后。服务扫描、Git采集、技能回放并非默认启动时急切执行。

曾试验 Copilot 登录公开模块仅在实际登录时加载，取消/卸载/加载失败测试和真实RPC认证冒烟均通过。
单独 dsh 交错实验出现约0.1秒中位改善，但真实便携包五组交错复核未复现：

| 轮次 | 第一轮便携包 | 懒加载候选 |
|---|---:|---:|
| 0 | 2.769s | 2.811s |
| 1 | 2.770s | 2.777s |
| 2 | 2.749s | 2.819s |
| 3 | 2.707s | 2.704s |
| 4 | 2.762s | 2.803s |
| **中位数** | **2.762s** | **2.803s** |

因此**撤回该候选的代码、测试和说明**，重新构建原介质；不以单模块 import 时间或不同批次的
偶然差值宣传整机收益。当前没有测到值得改变插件初始化时机的稳定收益。
