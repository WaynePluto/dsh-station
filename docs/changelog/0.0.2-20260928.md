# 0.0.2-20260928（2026-09-28）

预发布版本，0.0.2 系列的第五次迭代（并入 20260922、20260925、20260927 与本日
首轮说明）。版本号带日期后缀，GitHub Release 会标记为预发布。

## 发行介质：四个发布端 × lite/full

- Windows / macOS / Linux 桌面版 + Linux 服务版 zip，共四个发布端；win/mac 不再提供
  绿色包（服务版 zip）
- 每个介质分**轻量版（lite）/ 完整版（full）**；桌面版再分 **setup（安装包）**与
  **portable（便携 zip）**两种形态：Windows 是 NSIS `setup.exe`，macOS 是 DMG
  （拖入 Applications），Linux 是 deb
- 轻量版与服务版**不内置 Node.js**，要求系统 Node ≥ 22.19.0；桌面完整版（full）
  随包附带固定版本 Node（官方 SHA-256 校验，当前 24.21.0），装好即用
- full 变体额外携带 Office 文档预览的 LibreOffice 转换引擎：lite 打开 Office 文档
  预览会提示转换不可用，dsh 启动与其余功能不受影响，需要该功能就下载 full
- 发布命令按平台 × 变体拆分：`release`（本机全部）与 `release:win|mac|linux:lite|full`
  （`release:linux:<变体>` 同时产出服务版 zip）；推 tag 后由 CI 三个原生 runner
  （windows/macos/ubuntu）构建全部介质并汇总发布
- Windows 产物修复：NSIS 脚本写入 UTF-8 BOM，中文 Windows 不再 Bad text encoding；
  安装包改 lzma 固体压缩并接入应用图标，lite `setup.exe` 由 276.8 MB 降到 43.9 MB；
  桌面壳编译改 `-H=windowsgui` 子系统，双击不再先弹控制台窗口

## 桌面版（DSH 工作站）

- Wails v2 桌面应用：独立模式托管自有后台（dsh + relay + connector），双击即用；
  另有 attach 开发模式附着开发栈
- **本机模式（D25）**：桌面默认只启动 dsh 与项目插件，不再常驻 relay/connector
  ——省两个 node 进程与一个监听端口，远程能力从托盘「启用远程服务」按需启用
  （launcher 补起 relay + connector 后本机入口切回 relay；退出即回收，不记忆状态；
  CLI 与服务版仍全量启动）。本机入口由壳直连 dsh 的 loopback：token 经 desktop-link
  上报、初始导航 302 时代发一次 `/?token=` 交换（与 relay 代发的认证语义一致）。
  远程服务启动失败与本机隔离，不拖垮 dsh 工作台
- **统一启动生命周期**：开发（attach）与发行（独立）两种桌面模式共用同一套本机
  启动与远程按需启用流程；隔离环境端到端验证：状态流无 relay 阶段、直连交换 303、
  start-remote 后 relay 约 0.9 秒监听、connector 自动注册、stop 后 2.6 秒干净退出
- **托盘远程服务控制**：新增「停止远程服务」「重启远程服务」菜单，只回收远程
  子进程并保留本机 dsh 与会话；关闭远程前自动把内置 relay 页面导航回本机工作台；
  补齐开发命令转发、状态应答去重与远程生命周期竞态保护
- 自绘标题栏、托盘、桌面通知点击定位会话、应用图标统一；修复标题栏留白与
  本机标记配色
- Windows 实机验收通过（隔离数据 + 随包 Node、强制杀壳后 4 秒回收全部后台子进程、
  单实例互斥）；macOS/Linux 桌面版由 CI 原生 runner 构建，实机验收进行中
- 首次免设置：本机打开即是 dsh 工作台，无需先创建管理员；远程能力在管理界面按需开启
- 托盘收敛：移除启动/停止/重启后台三项（退出重开即等价于重启），失败/离线状态页
  指引改为「请退出并重新打开」
- 修复 launcher --desktop 停止后不退出：stdin 是活跃 handle 挂住事件循环，shutdown
  现在显式关闭控制通道（此前依赖壳退出断管或宽限期强杀兜底）
- 修复 mac/Linux 发行链路（首次在 CI 原生 runner 构建时暴露）：桌面壳不再交叉引用
  Windows 托盘符号；deb 打包支持 pnpm 的符号链接；补齐 macOS 链接缺失的
  UniformTypeIdentifiers 框架（wails v2.16.0 文件对话框所需）
- 修复 Windows 安装包缺失：makensis 探测增加 choco/官方安装器默认目录兜底，
  CI 上 setup.exe 不再被静默跳过

## 启动与管理加载页

- 弹终端修复：dev 栈链路改 `windowsHide`，启动全程 0 个控制台窗口
- **安全状态流驱动加载页**：启动 splash 与管理页加载统一由后台安全状态流驱动
  （状态事件经命令桥转发、应答去重），加载完成优先交接 dsh 原生界面；新增
  `docs/reference/startup-timing.md` 记录启动各阶段时序参考
- relay 提前到一切构建/同步之前启动（launcher 与 dev 栈都重排）；
  独立模式后台进一步与 WebView2 初始化并行
- 壳窗口不再等首次导航完成：Wails 默认要等初始导航 302 放行且首个页面加载完才显示
  窗口，冷启动下有数秒「点了没反应」；现改为 `OnStartup`（WebView2 就绪）立即显示，
  等待期间展示与 dsh 启动页同色的窗口底色
- 等待页由 relay 承担：本机 loopback 是复刻 dsh 启动页的 splash（HARNESS 字标 +
  进度弧转圈，meta refresh 每 0.2 秒重试、无脚本、CSP 不变，转圈外径逐像素
  对齐 dsh 启动页），机器上线后顺着 303 进 dsh；远程访客保留带指引的离线页
  （离线可能持续数小时，仍为每秒重试）
- 插件快路径以介质内容指纹替代开发栈 forceRefresh；dev 栈插件构建链按源码指纹跳过
  未变化构建（未变化省约 5s），dev 入口拆「运行时准备 + 栈主体」两段；dev:desktop
  以 mtime 缓存桌面壳产物替代每次 `go run` 链接（源码未变化省约 1.7s，selfcheck
  实测 0.28s 起壳）
- 实测：便携版开窗约 2.1–2.6 秒、dsh 可用约 6.2 秒（dsh 插件树加载为上游成本）；
  attach 模式开窗 2.5 秒、机器在线约 7.2 秒

## 管理页跟随原生主题

- 管理页单向消费工作站自有主题投影：remote-privileged 以只读投影暴露 dsh 原生
  主题，经 protocol 主题投影模块与 relay 主题事件/客户端下发到管理页；不读写
  原生 profile，认证边界与表单草稿行为不变
- 精简远程管理文案与信息层级，管理页面按机器真名展示

## 插件可管理、可卸载

- 20 个功能组件按用途组成 4 个组合包与 6 个独立第三方 Bundle，首次启动默认安装并启用
- 后续升级 dsh-station 配套升级仍安装的插件，并保留 Bundle 与组件的停用状态；
  卸载后不自动补回，可从随附 `plugins/` 目录重装
- 启动时把插件介质和运行依赖缓存到 profile 所在磁盘，并自动迁移不同 pnpm 主版本创建的
  `node_modules`，避免 Windows 跨盘链接或 store 版本变化导致启动直接退出
- remote-privileged 拆分：隧道连接所需的注入仍是不可停用的壳级补丁；远程设置进入
  远程体验组合包
- 修复组合 Bundle、简洁模式与固定 YOLO 在线停用时的 HMR 残留行；模型启动屏障在进程内
  保持稳定，10 个随附 Bundle 均可在线停用并重新启用
- 网页目录选择因需要整体覆盖原生选择器而独立分发；固定 YOLO 与简洁模式也保持独立 Bundle

## 界面与体验

- services 日志弹窗与 turn-retry 失败详情弹窗支持全屏切换，全屏时隐藏拖动与调整手柄
- services 常驻服务列表单行省略，长服务名不再把行尾按钮挤换行

  旧自启条目自动升级
- 术语统一：用户文案「精简模式」改为「简洁模式」，与预设界面一致
